# product-article-content-flow

> **本 change 已作废（2026-10-28），未进入实现。** 它被拆成两个各自可闭环、可独立验收与回滚的 change：`product-content-flow`（产品链，详情地址 `/product/:slug`）与 `article-content-flow`（资讯链，详情地址 `/article/:slug`），路由形态同时撤销了「统一详情地址 `/option/:type/:slug`」的决定，改由 `site-runtime-link-integrity` 收口。此处仅保留作决策沿革参考，请勿据此实施。

产品与资讯两条内容链闭环：管理端内容中心可录、录了能生效、官网列表与详情显示的是内容本身；资讯正文用富文本撰写且编辑不影响线上，前端 `views` 落成四个独立功能目录。

## 在全链路中的位置

第 1 步 `site-runtime-link-integrity` 定好「哪些地址存在、未发布即不可见」之后，本 change 把两条内容链填实。与第 2 步 `page-publication-approval`（只管 `pages` 表）无文件冲突；与第 3 步 `decoration-editor-toolkit` 只在「编辑器」这个词上重名——那一个改装修区块的表单，本 change 的富文本只服务资讯正文，两处不共用实现。可与它们并行推进，但详情地址的最终形态依赖 C1 的 `/option/:type/:slug` 落地。

## 规则口径

- 四个目录：管理端产品、管理端资讯、官网产品中心、官网新闻资讯；目录内自足（列表 + 编辑/详情 + 私有子组件与样式），产品与资讯的业务实现互不引用；正文编辑器是管理端资讯目录的私有子件
- 详情地址沿用统一形态 `/option/:type/:slug`，但实现拆在两个功能目录内部，**不再合并为单一 `Option.vue`**（此项修订同时落到 C1 的 design/tasks/spec）
- 管理端与官网的地址在目录重组中一字不改，重组可独立回滚；但本 change 第 3 组（目录落地）与 C1 第 3 组（`/option/:type/:slug` 路由指向两个目录的 `detail.vue`）需同批提交，否则路由会指向尚不存在的文件——不同批时 C1 第 3 组先挂原 `ProductDetail.vue` / `Article.vue` 路径
- 状态语义：产品 上架/下架（0|1），资讯 草稿/已发布/已下线（0|1|2），全站称谓统一
- 富文本组件定为 Tiptap 3（4 个包），能力边界由 `backend/src/lib.ts` 的清洗白名单反推：不提供对齐、字号、颜色、缩进、表格；白名单本身不放宽（见 design D10）
- 保存与发布分离：已发布资讯的编辑落成 `articles.draft_json` 未发布改动，官网只读正式列；发布在一个事务内覆盖并清草稿，空正文被拒绝（见 design D11）
- 三态分层：装修页未发布 → 整页 404；页面在而列表 0 条 → 列表区空态；请求失败 → 可重试错误态

## 关键交付物

- `proposal.md` — 断链的四个成因与 3 项 **BREAKING**（含「保存即生效」语义改变）
- `specs/product-content-flow/spec.md` — 录入字段、标识可变且唯一、图集/规格/卖点形态、上架即时生效、列表与详情渲染（6 项要求 / 23 个场景）
- `specs/article-content-flow/spec.md` — 富文本撰稿与清洗、三态状态机、草稿与线上分离、发布即时生效、列表与详情、浏览计数、分类删除保护（8 项要求 / 33 个场景）
- `specs/content-view-structure/spec.md` — 四目录归属、互不依赖、正文编辑器私有、地址不变、能力对齐、第三类内容的扩展（5 项要求 / 10 个场景）
- `design.md` — D1–D11 技术决策（含撤销 C1 合并方案、Tiptap 选型与草稿列的否决记录）、对既有 change 的修订、风险与迁移计划、6 个 Open Question
- `tasks.md` — 87 项任务，分 9 组（后端契约 → 迁移 010 → 目录落地 → 管理端产品 → 管理端资讯（含富文本接入）→ 官网产品 → 官网资讯 → 修订既有 change → 验证回滚）

## 为什么现在必须一起做种子数据

库里 `products`、`articles`、`banners` 均为 0 行，两条链无法端到端验收，C1 的「产品与资讯各取 3 条比对」也无从执行。迁移 `010_content_flow.sql` 种入 2+2 分类与 3+3 条内容（标题冠「示例」，图片用现有内置资产），附反向脚本；正式素材到位后由运营替换。种入的资讯正文只使用能力边界内的标签，因此种子行本身就是「编辑器产出 = 清洗后保留 = 官网渲染」三者一致的回归样本。

## 已识别的真实缺陷（本 change 的修复对象）

`PATCH` 丢 `slug`、`specs` 列默认 `{}` 与数组渲染形态漂移、`GET` 详情里写浏览量且被 `max-age` 缓存吞、删分类静默 `SET NULL`、产品与资讯的状态动作与文案不对称、详情页写死区头与占位假图、`Article.vue` 面包屑「新闻咨询」错别字、正文靠手写 HTML 且 `PATCH` 覆盖已发布内容的 `body` 让半成品直接上官网。
