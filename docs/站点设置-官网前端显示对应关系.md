# 站点设置 → 官网前端显示对应关系

> 核对时间：2026-11-04。基于当前工作区代码（未提交），逐字段按「配置项 → 存储 → 接口 → store → 前台渲染点」走查。
> 前台部分结论有浏览器实测支撑（本地 5190 首页 DOM），文中标「实测」；未标的是代码读查结论。
> 管理端入口：官网配置 → 站点设置（`/admin/config/settings`）。

## 一、取数与生效链路

| 环节 | 位置 |
| --- | --- |
| 存储 | `site_settings` KV 表（`key` 唯一 + `group_name` 分组 + `label`），`backend/sql/schema.sql:94-107`，种子 13 项见 `:468-482` |
| 后台读 | `GET /api/settings` → `backend/src/routes/content.ts:1287-1294`，返回 `group → key → {value,label}` |
| 后台写 | `PATCH /api/settings` → `content.ts:1296-1315`，逐条 upsert（新 key 可带 `groupName/label` 建档）+ 审计日志 |
| Logo 写 | `POST /api/upload/logo` → `backend/src/routes/upload.ts:107-132`，固定命名 `brand/logo.<ext>` 覆盖、换扩展名删旧图、把带 `?v=时间戳` 的 URL 直接写回 `logo_url` |
| 配置页 | `buinessweb/src/views/admin/website/settings.vue`：字段不是写死的，按接口返回的分组动态渲染；唯一特例是 `logo_url` 走上传控件（`:147-164`），其余统一是 `el-input`，值超 40 字符自动变 textarea（`:113-115`） |
| 公开接口 | `GET /api/public/site` → `backend/src/routes/public.ts:44-74`，一次返回 `settings`（按组）+ 三类导航；`cache-control: no-cache` + 内容 MD5 的 `ETag`，未变更走 304 |
| 前台状态 | `buinessweb/src/stores/site.ts:17-58`，`ensureLoaded(force)` 拉 `/public/site` 入 state，10 个 getter 在 `:27-37` |
| 前台渲染 | `buinessweb/src/layout/WebsiteLayout.vue`（官网全局壳层）+ `views/website/news/detail.vue:43`（资讯详情页标题拼接） |

生效时机有区别（重要）：
- 上传 Logo：`settings.vue:55` 会 `ensureLoaded(true)` 强制刷新站点配置 → 同一后台 SPA 里切回官网即见新图。**实测**。
- 其余文本字段：`save()`（`settings.vue:93-110`）**没有**调 `ensureLoaded(true)`。官网壳层只在挂载时 `ensureLoaded()`（`WebsiteLayout.vue:13`），所以已打开的官网页要刷新或重新进入才会更新。导航菜单页同样缺这一步。

## 三、页脚/顶栏里「不吃站点设置」的写死内容

这些位置看着像配置项，实际改站点设置不会变：

| 界面元素 | 来源 |
| --- | --- |
| 页脚白色 Logo 图 | 模板硬编码 `/website/img/logo-white.png`（`WebsiteLayout.vue:145`）。换 Logo 只换顶栏，页脚这张不动 |
| 页脚品牌介绍段落 | 模板硬编码（`:146`，「Centremix 芯联创 —— 2022 年与希捷工厂…」），后台无处可改 |
| 版权行「© 2026」与「· Centremix 芯联创」 | 模板硬编码（`:166`）；年份不会自动跳 |
| 浏览器标签标题（常规页面） | 路由守卫用硬编码常量 `BRAND = 'Centremix 芯联创'`（`router/index.ts:115-118`），装修页再由 `usePageBlocks.ts:32-43` 用 `pages.meta_title` 覆盖。**不使用 `site_name`，也不使用 `seo_title`** |
| 产品详情页标题 | 同样硬编码品牌名（`views/website/products/detail.vue:57`、`:74`） |
| 装修区块里的「TMALL 天猫旗舰店 ↗」按钮 | 内置默认内容硬编码外链（`website/pageDefaults.ts:142`），与 `social_tmall` 无关 |
| 顶栏导航 / 页脚分组列 / 右上角按钮 | 来自 `menus` 表（官网配置 → 导航菜单），不属站点设置 |

## 四、运营视角：改了不会生效的清单

| 你在后台改的 | 官网表现 | 原因 |
| --- | --- | --- |
| 品牌主色 | 不变 | 主色由 `assets/website.css` 静态变量决定，没有把 `brand_color` 注入 CSS 变量的代码 |
| SEO 标题 / SEO 描述 | 不变 | 前台没有任何读取点；标题走路由硬编码 + 页面级 `pages.meta_*` |
| 天猫店铺 / 小红书 | 不变 | 官网没有社交图标区，`site.social` 无人使用 |
| 品牌 Logo（上传） | 只有顶栏变 | 页脚是另一张硬编码白底图 |
| 任何文本字段（除 Logo） | 已打开的官网页不即时变，刷新后生效 | 保存流程没触发站点配置强刷（只有 Logo 上传触发了） |
| 站点名称 | 只影响顶栏 alt 与资讯详情页标题后缀 | 常规标签标题不吃它 |

## 五、口径补充

- 本页所述「页脚分组列」当前处于停用状态：`footerCols` 被注释为返回空数组（`WebsiteLayout.vue:47-49`，站点配置那路与内置兜底那路都以注释保留），实测页脚只剩品牌块 + 联系我们列。这与 `site_settings` 无关，属「导航菜单 → 页脚」那条链路，但会影响本节提到的页脚排版。
- `PATCH /settings` 允许新 key 建档（`content.ts:1305-1311`），也就是运营可自行往站点设置里加项；但前台只认上表里被引用的 key，新加项不会显示，也不会出现在管理页以外的地方。
- 后台另有两处独立配置入口不要混淆：品牌色与页面内容分别由「素材/装修」链路的 `pages.content_json` 区块和静态 CSS 决定，不吃 `site_settings`。
