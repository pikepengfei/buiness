## 1. 架构概览

```
bigscreenweb/ (Vue3 SPA)
├── 设计系统  src/assets/website.css      ← 由官网设计 style.css 迁移（品牌橙 #DE6420，响应式）
├── 类型     src/types/cms.ts             ← 与后端 /api 返回结构对齐
├── API 客户端 src/api/cms.ts             ← axios 封装（公开/鉴权/表单）
├── 全局态   src/stores/site.ts           ← Pinia：站点设置 + 导航（一次拉取，全站共享）
├── 布局     src/layout/WebsiteLayout.vue  ← 顶部导航 + 页脚（全局包裹营销页）
├── 页面     src/views/website/*.vue       ← 9 个官网页面
├── 装修区块 src/website/sections/*.vue     ← 19 种模块区块 + SectionRenderer 递归渲染
├── 公共元素 src/components/ui/*.vue        ← 4 个基础元素（文字/标题组/图片/按钮），区块与 children 共用同一份实现
├── 后台装修 src/views/admin/website/       ← 页面列表 + 装修编辑器 + 组件库面板
└── 路由     src/router/index.ts           ← 营销站根路径 + /admin 后台骨架
        │
        └── HTTPS /api ──▶ 后端 Fastify ──▶ PostgreSQL + 对象存储
```

设计原则：
- **营销站与后台分离**：`/` 起为官网（WebsiteLayout 包裹），`/admin` 起为运营后台骨架（沿用既有 admin 模板）。
- **数据驱动**：页面通过 `cms`（公开只读接口）拉取产品/资讯/Banner/设置，CMS 后台改完即时生效，无需发版。
- **设计系统复用**：原型 CSS 整体迁移为 `website.css`，类名（`.hero/.stats/.sec/.area/.product/.contact-form/...`）原样复用，保证视觉一致。
- **基础元素单一实现、两处用法**（`home-decoration-components` D3）：按钮/标题/文字/图片只有 `src/components/ui/` 这一份实现（`UiButton` / `UiHeading` / `UiText` / `UiImage`，`index.ts` 统一导出）。同一份实现服务两个调用方——① 模块区块内部（`sections/Sec*.vue` 直接 import 使用，版式类名仍由所在模块的 scoped 样式提供）；② 模块的 `children` 子内容（`SectionRenderer.vue` 按 `layer==='atom'` 直接把注册表里的同一个组件 `v-bind="atomBindProps(type, props, preview)"` 渲染，不另建装修专用壳组件；`atomBindProps` 只把 `preview` 追加给**声明了该 prop** 的元素，所以「图片未选择」「跳转地址不合法」两类编辑态提示在子内容层同样生效、官网态不出现，未声明的 `UiText`/`UiHeading` 也不会多出 `preview` DOM 属性）。`sections/SecHead.vue` 已改为转发 `UiHeading` 的薄组件，14 处调用点不改。新增需求优先扩 `ui/` 元素的 props，MUST NOT 在模块内重写一份按钮/标题样式；页面级视觉微调仍留在该页组件的 scoped style，不改 `website.css` 与全局 tokens。
- **子内容落位**：模块区块在自身版式内保留 `<slot />`，`SectionRenderer` 把 `children` 递归塞进该插槽（只有声明了 `accepts` 的模块有子内容位）。「哪类元素能进哪类模块」由注册表的 `accepts`/`allowedIn` 在**编辑器侧**把关（插入时置灰 + 保存前 `validateTree` 复核深度/重复 id/子内容数）；后端只校验树骨架结构与上限，不维护类型清单，直接调接口仍可存入未被接受的子内容——这是已知边界，不作为接口层的安全保证。

## 2. 页面 ↔ 路由 ↔ 数据映射

| 原型（官网设计/） | 路由 | 组件 | 数据来源 |
|---|---|---|---|
| `index.html` | `/` | `website/Home.vue` | `/public/banners(home)` `/public/products`(精选) `/public/articles`(最新) |
| `about.html` | `/about` | `website/About.vue` | 静态品牌文案（可接 `/public/pages/about`） |
| `products.html` | `/products` | `website/products/index.vue` | `/public/product-categories` + `/public/products`(筛选/搜索/排序/分页) |
| `product-detail.html` | `/product/:slug`（正式）<br>`/products/:slug`（旧，并存待 C1 移除） | `website/products/detail.vue` | `/public/products/:slug`(画廊/规格/亮点/相关) |
| `news.html` | `/news` | `website/news/index.vue` | `/public/article-categories` + `/public/articles`(分页) |
| `article.html` | `/article/:slug`（正式）<br>`/news/:slug`（旧，并存待 C1 移除） | `website/news/detail.vue` | `/public/articles/:slug`(富文本 `v-html`/相关) |
| `contact.html` | `/contact` | `website/Contact.vue` | `/public/faqs` + `formApi.submitContact` |
| `search.html` | `/search` | `website/Search.vue` | `/public/search?q=` |
| `404.html` | `/:pathMatch(.*)*` | `website/NotFound.vue` | 静态（顶层路由，自带 nav/footer） |

> 站内链接一律指向**正式地址** `/product/:slug`、`/article/:slug`；旧地址只保留一条与正式地址同组件的路由记录，用于兜住已分发的外链与收藏夹，移除归 C1 `site-runtime-link-integrity` 第 3 组，不属于内容链的改动范围。

### 2.1 内容中心（管理端）目录与路由

```
src/views/admin/content/
├── product/                 # 产品链（本链）
│   ├── index.vue            # 列表：/admin/content（内容中心首叶即产品列表，路径规则见 adminMenu.ts）
│   ├── edit.vue             # 新建/编辑/查看三合一：/admin/content/products/edit/:id?
│   ├── categories.vue       # 产品分类：/admin/content/product-categories
│   └── components/          # 本页私有子件，不被其它目录引用
│       ├── DescriptionEditor.vue   # 描述富文本（Tiptap 私有实例）
│       ├── GalleryEditor.vue       # 图集（≤8，存可直接渲染的图片地址）
│       └── SpecsEditor.vue         # 参数表（≤20，{label,value} 有序数组，行序即展示序）
└── article/                 # 资讯链，与本目录零相互 import
    ├── index.vue / edit.vue / categories.vue
    └── components/RichBodyEditor.vue   # 资讯正文编辑器，产品侧不引用
```

- **官网侧同构分目录**：`src/views/website/products/{index.vue,detail.vue}` 与 `src/views/website/news/{index.vue,detail.vue}` 各成一组，两链互不 import；产品详情页只消费 `/public/products/:slug` 下发的列（分类名以 `category` 字段给出，为 `null` 时不渲染该区，不回落写死文案），读不到行即渲染品牌化 404。

- **同一个编辑页承载三种形态**：`/edit`（新建草稿）、`/edit?draft=<草稿行 id>`（编辑未上架）、`/edit/<线上行 id>`（查看已上架）。已上架形态整页只读，保存/发布/删除入口都不渲染，页面头部给出「已上架内容只读」的说明与下架入口。
- **行 id 与内容身份是两回事**：列表行的 `origin` 决定该 id 属于哪张表，编辑页据此选读取端点；写请求除行 id 外还 MUST 带上 `uid`，两者不符服务端返回 409，前端把服务端那句原话直接作为错误提示显示，不另算一套文案。
- **标识（`slug`）前端不填、不改、不推导**：产品与资讯的编辑页、两个分类弹窗都取消了标识输入框，原位置换成只读展示——新建时显示「保存后自动生成」，`POST` 响应把生成的值带回并立即回显，编辑时取自行数据；展示位下方给出对应的官网详情地址（`/product/{slug}`、`/article/{slug}`）。表单提交体不含 `slug`，改名后该值不变，前端也不在前端侧生成候选标识。
- **列表按钮形态只由 `origin` + `state` 渲染**：`origin='online'` → 查看 / 下架 / 调整排序；`origin='draft'` → 编辑 / 发布 / 删除；只有持 `content:write` 的账号渲染写入口。状态列直接显示服务端下发的 `state_text`（称谓单点在 `PRODUCT_STATE_TEXT`），前端只另有一份「状态 → 标签颜色」映射 `STATE_TAG`；筛选下拉的三个选项标签与审计时间线里的状态枚举转译是页面里仅有的两处中文硬编码，改称谓时必须与后端常量同步。

## 3. 设计系统

- **品牌色**：橙 `#DE6420`（VIS 硬约束，与实现稿 `style.css` 一致）。Site store 暴露 `brandColor` 供布局取用。
- **字体**：系统字体栈（PingFang SC / Microsoft YaHei），无外部字体依赖，离线可渲染。
- **响应式断点**（沿用原型）：≤1100px 4 列→2 列；≤640px 单列，导航折叠为汉堡抽屉（`.mnav` 由 `WebsiteLayout` 的 `mobileOpen` 控制）。
- **图片资源**：原型 `assets/img/*` 已复制到 `public/website/img/`，页面以 `/website/img/...` 引用（Vite 静态服务）。

## 4. 数据获取与状态

### 4.1 API 客户端 `src/api/cms.ts`
- `cms.*`：公开只读接口（`getSite/getBanners/getProducts/getProduct/getArticles/getArticle/getFaqs/search` 等）。
- `authApi.*`：登录/登出/me（写入 `localStorage.Authorization`）。
- `formApi.*`：询价/合作/订阅/联系提交。
- axios 拦截器自动附加 `Authorization`；401 自动清理令牌。

### 4.2 站点全局态 `src/stores/site.ts`
`WebsiteLayout` 挂载时调用 `site.ensureLoaded()` 拉取 `/public/site`（设置分组 + 导航树），并通过 getter 暴露 `siteName/slogan/contactEmail/contactPhone/address/icp/social` 供所有页面/页脚复用。

### 4.3 页面约定
- 列表/详情页统一 **loading + 空状态**；详情页带「未找到」兜底。
- 富文本用 `v-html` 渲染（后端已 `sanitize-html` 清洗，安全）。
- 详情链接一律由代码生成、指向正式地址（产品 `/product/${slug}`、资讯 `/article/${slug}`），杜绝硬编码 `.html` 与旧详情段。

## 5. 表单与线索

`website/Contact.vue` 等通过 `formApi.submitContact/submitInquiry` 提交，流程：
1. 前端基础校验（必填、邮箱格式、隐私同意勾选）。
2. `POST /api/forms/*`（后端已限流 20 次/60s）。
3. 成功/失败以页面内 Toast 反馈；失败不抛白屏。
4. 后端入库并预留邮件通知（见《后端执行文档》7.2）。

## 7. 构建与部署

```bash
npm install
npm run build          # Vite 产出 dist/ 静态资源
# 静态托管：对象存储 + CDN（推荐），或 Nginx
```
- **静态资源**：`dist/` 上传至对象存储（公共读）+ CDN 加速；`/api` 反代到后端。
- **SPA 路由**：Nginx 对 `*` 回退 `index.html`（避免刷新 404）。
- **HTTPS**：全站强制 TLS；HSTS。

### SEO 与性能（需求文档非功能需求）
- 关键页（首页/产品/资讯）建议改用 **SSG/SSR**（Nuxt / Vite SSR）以优化收录；当前 SPA 已做语义化结构、`meta` 由 Site store 注入。
- 图片 WebP 化、`loading=lazy`、JS 按需分包；首屏 LCP < 2.5s。
- 结构化数据：Organization / Product / Article（SEO 模板预留）。

### 发布前检查（区块结构版本相关）
区块内容带 `children`（模块装载基础元素）属于结构版本 2，旧渲染器读到会忽略 `children`、把模块渲染成空壳，因此上线顺序固定为：

1. **先发前端**：确认 `buinessweb/src/website/blocks.ts` 的 `RENDERER_SUPPORTED_SCHEMA_VERSION >= 2`，且 `SectionRenderer.vue` 已具备递归分发能力。
2. **验证官网正常**：用改造前的历史页面 JSON（不含 `children`）访问首页与其余导航页，逐页比对截图。
3. **再放开编辑器**：允许运营在组件库里把基础元素插进模块内。
4. **最后跑数据迁移**（如 `013_home_module_seed.sql`）。

编辑器保存草稿与发布前都会调 `nestedSaveGuardMessage(blocks)`：常量低于 2 且内容含 `children` 时拒绝保存并提示原因（`views/admin/website/pages/editor.vue` 的 `saveDraft`），因此第 1 步未做完时不会出现「库里已有嵌套内容、官网显示空壳」的中间态。回滚前端到旧版本前，需先确认库内没有带 `children` 的页面内容。

## 8. 组件库抽屉与真实预览（2026-11-10）

目录职责：

- `src/website/libraryDemoData.ts`：组件库预览的占位样例（产品 / 资讯 / FAQ / 分类），纯数据、不 import 注册表，避免循环引用。
- `src/website/libraryDemo.ts`：`libraryDemoBlocks(type)` 由注册表 `defaultProps()` 与示例子内容构造 demo Block，幂等、不落库。
- `src/views/admin/website/components/LibraryCard.vue` / `LibraryGrid.vue`：组件库卡片与网格；卡片自行用 `IntersectionObserver` 懒渲染，无该 API 的环境只留占位框。
- `src/views/admin/website/components/ComponentLibraryPanel.vue`：抽屉内容，保留搜索、分组、目标位置提示与插入判据（权限 / 位置 / 上限三层）；顶部 `el-tabs` 分「组件库 / 模板库」两标签页，抽屉标题「组件库与模板」。
- `src/views/admin/website/components/BlockTemplatePanel.vue`（decoration-editor-toolkit）：「模板库」标签页内容——列表（关键词 + 类型过滤 + 分页）、存为模板（对编辑器当前选中区块命名入库，重名可二次确认覆盖）、从模板插入（emit 给编辑器按 moduleTarget / atomTarget 插入）、改名 / 删除（二次确认）、「铺入默认内容」入口（仅 `defaultBlocks(slug)` 非空的页面显示）。插入判据与组件库同口径（权限 / 类型可用 / 目标 / 上限），`LibraryCard` 加可选 `blocks?: Block[]` prop 渲染模板自身内容，不传时回落类型默认骨架、组件库调用方零变化。

约定：

- 预览样式与官网同源：卡片根挂 `web-scope` 并 `@import '@/assets/website.css'`（由浏览器解析、不受 scoped 影响，与 `WebsiteLayout.vue` / `editor.vue` 同法），模块用 `transform: scale()` 定宽缩放。
- 抽屉只由编辑器右侧打开（rtl、480px、`:append-to-body="false"`、`modal=false` + `modal-penetrable=true`），不新增路由与后台菜单入口；`editor.vue` 的 `.ed-body > .el-overlay { position: absolute }` 是定位关键，删掉会把顶栏一起盖住。
- `SectionRenderer` 的 `demo` 属性只在组件库预览传，且只向 `DATA_DRIVEN_TYPES` 透传，避免其它模块根元素多出 DOM 属性；5 个数据驱动区块在 `demo` 模式下跳过接口调用。
- `decoration-editor-toolkit` 已落地：模板面板复用 `LibraryCard` 渲染模板缩略（可选 `blocks` prop），编辑器结构树新增拖拽排序（同层同父）、行内同页复制 ⧉ / 跨页复制 ⇄、勾选批量删除与批量存模板；`src/website/blocks.ts` 新增 `mergeBlockProps(type, props)`（模板 props 兼容合并）与 `isTemplateUsable(type)`（类型在注册表即可用，模块与基础元素双层）。
