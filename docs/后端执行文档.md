## 1. 架构概览

```
┌────────────────┐         HTTPS          ┌──────────────────────────┐
│  官方前台(Vue)  │ ──── /api/* ─────────▶ │  Fastify 网关 (Node)      │
│  z-buiness/     │                        │  ├─ CORS / 限流          │
│  bigscreenweb   │                        │  ├─ JWT 鉴权中间件        │
└────────────────┘                        │  ├─ 路由: auth/users/     │
        │ 浏览器直传                        │  │  content/forms/upload/  │
        │ (预签名 PUT)                      │  │  public                │
        ▼                                  └───────────┬──────────────┘
┌────────────────┐                                     │ SQL / SDK
│ 云端对象存储    │ ◀──── presignPut (浏览器直传) ────────┤
│ (S3 兼容/CDN)  │                                     ▼
└────────────────┘                              ┌──────────────────┐
                                              │ 云端 PostgreSQL  │
                                              │ (Supabase/RDS)   │
                                              └──────────────────┘
```

设计要点：
- **后端只做 API**，不渲染页面；富文本/页面内容由前端按需获取。
- **文件不走后端流量**：前端先 `POST /api/upload/presign` 拿预签名 URL，浏览器直传对象存储（节省带宽、降低后端负载）。
- **公开只读接口**（`/api/public/*`）与**受保护接口**（CMS/用户/线索）分离，RBAC 在路由层强制。

## 3. 鉴权与 RBAC

### 3.1 双令牌（Access + Refresh）
- **Access Token**：JWT，`expiresIn` 默认 `2h`，携带 `sub=用户ID`；每个受保护请求经 `Authorization: Bearer <token>` 校验。
- **Refresh Token**：JWT，默认 `14d`；仅存 **SHA-256 哈希** 于 `user_sessions`，原始令牌下发后即丢弃；登出/刷新时吊销。
- 登录写入 `login_logs`（成功/失败原因），并刷新 `users.last_login_*`。

### 3.2 角色与权限点
`roles.permissions` 为 JSONB 数组；`super_admin` 为 `["*"]`，通配放行。当前权限点：
| 权限点 | 含义 | 默认角色 |
|---|---|---|
| `user:write` | 用户/角色管理 | super_admin |
| `content:read` | 查看 CMS 内容 | editor / operator |
| `content:write` | 增删改 CMS 内容 | editor |
| `media:write` | 上传/媒体库 | editor |
| `lead:read` | 查看表单线索 | operator |
| `lead:write` | 更新线索状态 | operator |

中间件：`authPreHandler`（校验令牌并装载 `req.user`）、`requirePerm(perm)`（校验权限点）。

## 4. 接口定义（总表）

> 基础路径 `API_PREFIX=/api`。公开接口无需令牌；受保护接口需在 Header 带 `Authorization: Bearer <accessToken>`。

### 4.1 鉴权 `/api/auth`
| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| POST | `/auth/login` | 公开 | 用户名+密码登录，返回 access/refresh token 与 user |
| POST | `/auth/refresh` | 公开 | 凭 refreshToken 换新的 accessToken |
| POST | `/auth/logout` | 公开 | 吊销 refreshToken（登出） |
| GET  | `/auth/me` | 需登录 | 返回当前用户信息 |

### 4.2 用户与角色
| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET  | `/users` | user:write | 用户列表（分页） |
| POST | `/users` | user:write | 新建用户（密码 bcrypt 哈希） |
| GET  | `/users/:id` | user:write | 用户详情 |
| PATCH| `/users/:id` | user:write | 更新资料/角色/状态/重置密码 |
| DELETE| `/users/:id` | user:write | 删除用户（不可删自己） |
| GET  | `/roles` | 登录 | 角色列表 |

### 4.3 内容管理 CMS
| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET/POST | `/pages` | read/write | 单页（关于/公司介绍等）列表/新建 |
| GET/PATCH/DELETE | `/pages/:id` | read/write | 单页详情/更新/删除 |

## 5. 关键实现说明

### 5.1 内容提交与 XSS
富文本字段（`articles.body`、`faqs.answer`、`pages.content_json` 的字符串叶子）入库前经 `sanitize-html` 清洗，仅放行安全标签与 `http(s)/data/mailto` 协议，防止存储型 XSS。前端使用 `v-html` 渲染时是安全的。

### 5.2 文件上传（云端直传）
1. 前端 `POST /api/upload/presign {filename,contentType,category}` → 后端 `genObjectKey()` 生成 `category/yyyyMM/uuid.ext`，调用 S3 `PutObjectCommand` 生成 **600s 有效预签名 URL**。
2. 浏览器以 `PUT` 直传对象存储（不经后端，节省流量）。
3. 上传完成后前端 `POST /api/media` 登记媒体库记录（objectKey → 返回 CDN URL）。
- 本地开发：`STORAGE_DRIVER=local` 时走 `/api/upload/direct`（multipart 写入 `STORAGE_LOCAL_DIR`，并以 `/uploads/...` 静态提供）。

### 5.3 状态机与审计
- 线索表 `inquiries/cooperation/contact_messages` 统一 `status`：`0新线索 / 1跟进中 / 2已成交 / 3无效`，支持 `handled_by` + `note`。
- 所有 CMS 写操作写入 `audit_logs`（操作人/IP/前后差异），满足需求文档 CMS-06 审核留痕。

## 6. 部署要点

### 6.1 环境变量（`.env`）
参见 `.env.example`：`DATABASE_URL`、`JWT_SECRET`、`JWT_REFRESH_SECRET`、`STORAGE_*`、`RATE_LIMIT_*`、`BCRYPT_ROUNDS`。**密钥请用 `openssl rand -hex 32` 生成，禁止提交仓库。**

### 6.2 构建与运行
```bash
npm install
psql "$DATABASE_URL" -f sql/schema.sql
ADMIN_USERNAME=admin ADMIN_PASSWORD='Admin@123456' npm run setup-admin
npm run build            # tsc -> dist
NODE_ENV=production node dist/server.js
# 或开发： npm run dev
```
生产建议用 `pm2` 或容器化（`Dockerfile` 可基于 `node:20-alpine`，暴露 3000）。

### 6.3 反向代理与 HTTPS
Nginx/Caddy 终止 TLS（全站 HTTPS），`/api` 反代到 `localhost:3000`，`/uploads`（本地模式）与对象存储走 CDN。CORS 通过 `FRONTEND_ORIGIN` 限制来源；表单接口已启用 `@fastify/rate-limit`（默认 20 次/60s）防滥用。

### 6.4 安全与合规
- 全站 HTTPS；接口鉴权 + RBAC；密码 bcrypt(cost=12)；refreshToken 仅存哈希。
- 个人信息最小化收集，表单需勾选隐私同意（前端实现）；预留导出/删除接口供合规。
- 定期备份：数据库每日 `pg_dump` + 对象存储版本化/异地复制（详见《数据库执行文档》）。

### 6.5 与前端联调
前端 `src/api/cms.ts` 以 `VITE_API_BASE`（默认 `/api`）为基址；前后端同源部署时无需额外配置，跨域时设置 `VITE_API_BASE=https://api.example.com/api` 并放宽 `FRONTEND_ORIGIN`。
