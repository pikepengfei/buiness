# 数据库执行文档 · Centremix 芯联创企业官网

> 配套：`sql/schema.sql`（建表+种子）、`数据结构文档.md`（字段明细）
> 数据库：**PostgreSQL 14+**（云端托管）。所有表结构、索引、种子数据以 `schema.sql` 为唯一事实来源。

---

## 1. 选型与定位

| 维度 | 推荐 | 说明 |
|---|---|---|
| 引擎 | **PostgreSQL 14+** | 原生 JSONB（规格/图集/标签）、GIN 全文检索、稳定可靠 |
| 托管 | **Supabase** / 阿里云 RDS PostgreSQL / 腾讯云 PostgreSQL | 兼容 `pg` 驱动，迁移零成本 |
| 连接 | 连接池（后端 `pg.Pool`，max=10） | 避免短连接风暴 |
| 字符集 | UTF8 | 中文内容必备 |

> **选型结论（自建 ECS/物理机 + 最佳实践）**：保持 **PostgreSQL 14+**。本负载同时需要「强关联（用户-角色-内容-线索）」与「半结构化（规格/图集/标签/富文本）」，PostgreSQL 的 JSONB + GIN 全文检索 + 强事务最契合，且 `schema.sql` 已基于此实现、后端 `pg` 驱动就绪，零返工。MySQL 在自建场景下亦可（需改写 JSONB/FULLTEXT 与驱动），MongoDB 不推荐（牺牲关联与事务）。详见 §3.3、§3.4。

## 3. 数据库开通与连接

> 本项目部署形态为 **自建 ECS / 物理机**（已确认），首选 **§3.3 自建部署**；§3.1/§3.2 为可选的云托管方案，能力等价、运维更省心，可按需切换（连接串一致，业务代码无需改动）。

### 3.1 Supabase（云托管，开箱即用）
1. 新建 Project → 得到连接串 `postgres://postgres:[pw]@db.<ref>.supabase.co:5432/postgres`。
2. 将连接串填入后端 `.env` 的 `DATABASE_URL`。
3. SQL Editor 执行 `sql/schema.sql`（或在 CI 中用 `psql` 执行）。
4. 启用 Row Level Security 仅当直接用 Supabase 客户端时；本方案后端经服务账号统一访问，应用层已做鉴权。

### 3.2 云厂商 RDS（阿里云/腾讯云）
- 创建 PostgreSQL 实例，开启 **SSL** 与 **VPC 内网白名单**（仅放行后端 ECS/容器网段）。
- `DATABASE_URL` 使用内网地址以降低延迟与费用。
- 如需强制 SSL：`postgres://user:pw@host:5432/db?sslmode=require`。

---

### 3.3 自建 ECS / 物理机部署（本项目推荐路径）

**容器化（推荐）**：用 `docker-compose` 起 PostgreSQL 16，数据落盘到命名卷，**仅对内网/本机端口开放**，不暴露公网。

```yaml
# docker-compose.yml（仅数据库）
services:
  postgres:
    image: postgres:16-alpine
    restart: always
    environment:
      POSTGRES_USER: centremix
      POSTGRES_PASSWORD: <强密码，来自密钥管理/KMS>
      POSTGRES_DB: centremix
    ports:
      - "127.0.0.1:5432:5432"   # 仅监听内网/本机，禁止公网暴露
    volumes:
      - pgdata:/var/lib/postgresql/data
    command: ["postgres", "-c", "shared_buffers=256MB", "-c", "max_connections=200"]
volumes:
  pgdata:
```
初始化（将 `sql/schema.sql` 挂载进容器或 `docker cp` 后执行）：
```bash
docker compose exec -T postgres psql -U centremix -d centremix -f /docker-entrypoint-initdb.d/schema.sql
# 或本地： psql "$DATABASE_URL" -f sql/schema.sql
```

**连接池**：后端 `pg.Pool(max:10)` 已满足一般并发；高流量可前置 **PgBouncer**（transaction 模式）复用连接，避免短连接风暴。
**安全**：防火墙仅放行后端 ECS 网段；启用 SSL（`DATABASE_URL` 加 `?sslmode=require`）；数据库账号最小权限（仅 DML，无 DDL）。
**备份**：每日 `pg_dump` 落本地并同步到对象存储（开启版本控制）；建议开启 WAL 归档以支持 PITR。
**监控**：关注连接数、慢查询（后端已对 >200ms 记录日志）、磁盘空间与复制延迟。

### 3.4 切换引擎的代价（如改 MySQL / MongoDB）
- **MySQL**：需将 `JSONB→JSON`、`to_tsvector GIN→FULLTEXT`、部分函数与 `ILIKE→LIKE` 改写，后端驱动 `pg→mysql2`，改动中等，且全文检索能力弱于 PG。
- **MongoDB**：需放弃关系模型、重写为文档集合，跨文档事务受限；对本 CMS 改动最大、收益最低，**不推荐**。

## 4. 初始化步骤

```bash
# 1) 建表 + 种子（角色/站点设置/导航）
psql "$DATABASE_URL" -f sql/schema.sql

# 2) 创建首个管理员（密码经 bcrypt 哈希，仅存哈希）
ADMIN_USERNAME=admin ADMIN_PASSWORD='Admin@123456' ADMIN_EMAIL=admin@centremix.com \
  npm run setup-admin
```
种子包含：`roles`（super_admin/editor/operator）、`site_settings`（站点名/Slogan/品牌色/联系方式/SEO/社媒）、`menus`（5 个一级导航）。**品牌色采用 `#DE6420`（橙）**，与官网设计稿 `style.css` 及需求文档 VIS 硬约束一致（设计分析曾提红 `#E40013`，以 VIS 与实现稿为准）。

## 5. 索引与性能

- 所有 `slug` 唯一索引 → 作为公开路由标识（不可枚举性优于自增 ID）。
- `articles` / `products` 建立 `to_tsvector('simple', ...)` GIN 索引 → 支撑 `/public/search` 全站检索。
- 列表查询按 `status + (published_at|sort)` 复合索引；外键列已建索引。
- 单表千万级内无需分区；超大规模可对 `articles` / `audit_logs` 按 `created_at` 范围分区演进。

## 6. 备份与恢复（非功能需求：每日自动）

```bash
# 每日全量（cron 02:00）
pg_dump "$DATABASE_URL" | gzip > /backup/centremix_$(date +%F).sql.gz

# 恢复
gunzip -c /backup/centremix_YYYY-MM-DD.sql.gz | psql "$DATABASE_URL"
```
- 云托管实例建议开启 **PITR（时间点恢复）** + 跨区副本。
- 大表 `audit_logs` 可保留 180 天后归档至冷存储。
- 对象存储（图片/文件）开启 **版本控制 + 异地复制**，与数据库备份解耦。

## 7. 安全与合规

- **最小权限**：后端使用专用数据库账号（仅 `SELECT/INSERT/UPDATE/DELETE`，无 `SUPERUSER`、无 DDL）。
- **传输加密**：强制 `sslmode=require`；网络层仅放行后端网段。
- **密钥隔离**：`DATABASE_URL` 来自环境变量/密钥管理（Vault/KMS），不入库、不进 Git。
- **个人信息**：`inquiries/contact_messages` 中的 phone/email 属个人敏感信息，按隐私政策最小化收集，预留导出/删除接口满足合规。

## 8. 迁移与演进

- 本方案以 `schema.sql` 为基线；后续变更建议引入 **迁移工具**（Flyway / Liquibase / Prisma Migrate）管理增量版本，避免手工改表。
- 接入 **WorkBuddy 云端数据库 / Supabase** 时，`DATABASE_URL` 切换即可，业务代码无需改动（驱动为 `pg`，跨 PG 兼容）。
