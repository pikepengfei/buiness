# 官网低代码装修平台 · 设计与实施文档

> 版本：v1.0 ｜ 范围：buinessweb（Vue3 前台 + 管理端）+ backend（Fastify CMS）
> 目标：官网前端「固定宽度与结构」，由管理端对页面内容与区块进行编辑、草稿、发布，实现类低代码的「区块装修」能力，并保证每个后台功能操作闭环。

---

## 1. 需求背景与设计目标

### 1.1 原始需求
1. 官网前端每个导航对应页面的功能组件与显示内容，均可由管理端编辑与发布。
2. 官网前端固定宽度与结构（版式由样式体系保证），管理端只编辑「内容」，不改样式结构。
3. 从设计到落地的详细文档输出。
4. backend 新增所需接口并输出接口文档。
5. 前端每个功能操作闭环（列表 → 新增/编辑 → 保存提示 → 刷新；删除带确认）。

### 1.2 设计目标
- **区块化内容模型**：页面 = 有序「区块（Block）」列表，数据结构统一、可扩展、可版本化。
- **草稿 / 正式双版本**：管理端编辑保存进草稿，发布时覆盖线上，官网永不因编辑产生半成品。
- **结构固定、内容可编辑**：19 种区块各有一套既定版式（沿用 `assets/website.css`），管理端通过通用表单编辑 `props`，不能改动布局与样式，契合「固定宽度与结构」诉求。
- **完整版 CMS 闭环**：页面装修 + Banner + 导航 + 站点设置 + FAQ + 产品/分类 + 资讯/分类 + 媒体库 + 线索 + 用户 + 审计，全部在管理端可视操作。
- **零新增重依赖**：富文本用 HTML 源码编辑 + 切换预览，不引入富文本编辑器库；图片上传沿用现有本地直传 / 预签名方案。

## 2. 总体架构

```
┌──────────────────────── 官网前台（views/website）────────────────────────┐
│  WebsiteLayout（顶部导航/页脚：/public/site）                              │
│  Home / About / Products / News / Contact —— 区块驱动渲染                  │
│         └── SectionRenderer.vue  ← usePageBlocks(slug) ← cms.getPage       │
│               └── SECTION_REGISTRY[type].component（19 个 Sec*.vue）        │
└──────────────────────────────────────────────────────────────────────────┘
                                 ▲ content_json（status=1）
                                 │
┌──────────────────── 管理端（views/admin，/admin，需登录）─────────────────┐
│  页面装修编辑器 editor.vue：左区块列表 / 中 BlockForm / 右 SectionRenderer  │
│  内容 / 配置 / 线索 / 素材 / 系统 各管理页 → cmsAdmin（对齐后端 /api）      │
└──────────────────────────────────────────────────────────────────────────┘
                                 ▲ by-slug / draft / publish / CRUD
                                 │
┌──────────────────────── backend（Fastify + PostgreSQL）───────────────────┐
│  routes/content.ts  pages(双版本)/products/articles/categories/banners/    │
│                     faqs/settings/menus/media + audit                      │
│  routes/forms.ts    inquiry/cooperation/contact 提交 + leads 管理/统计      │
│  routes/upload.ts   presign / direct 上传    routes/users.ts 用户/角色      │
│  pages: content_json(线上) | draft_json(草稿)  均为 { blocks:[...] }        │
└──────────────────────────────────────────────────────────────────────────┘
```

### 2.1 内容模型
```ts
interface PageContent { blocks: Block[] }
interface Block {
  id: string;                     // 区块实例 id（前端 genBlockId 生成）
  type: string;                   // 区块类型，对应区块注册表
  visible: boolean;               // 显隐开关
  props: Record<string, any>;     // 内容数据（文案/图片/列表项），不含样式
}
```
- `pages.content_json`：线上正式版本，官网前台读取渲染（仅 `status=1`）。
- `pages.draft_json`：管理端草稿版本，编辑器保存写入，发布时覆盖 `content_json`。
- 二者结构完全一致，均满足 `{ blocks: Block[] }`。

## 3. 区块体系（19 种）

区块注册表：`buinessweb/src/website/sectionRegistry.ts`，每种类型注册
`{ label, group, component(markRaw), defaultProps(), formSchema }`。管理端「新增区块」按 `SECTION_GROUPS`（头部与首屏 / 图文内容 / 数据驱动 / 转化组件）分组展示。

| type | 名称 | 分组 | 数据驱动 | 关键 props |
|---|---|---|---|---|
| hero | 首页首屏 Hero | 头部与首屏 | 否 | eyebrow、title[]、lede、cta1/cta2、meta[]、image、imageAlt、floaterLeft/Right |
| page-hero | 内页头图 | 头部与首屏 | 否 | crumb、title[]、subtitle |
| intro-eco | 品牌/公司介绍三栏 | 图文内容 | 否 | eyebrow、title[]、desc、items[{h4,p}] |
| mvv | 使命与愿景 | 图文内容 | 否 | eyebrow、title[]、desc、theme、cards[{tag,text}] |
| values | 品牌价值观 | 图文内容 | 否 | eyebrow、title[]、desc、items[{icon,title,en,text}] |
| timeline | 时间轴（历程/流程） | 图文内容 | 否 | eyebrow、title[]、desc、theme、items[{year,title,text}] |
| story | 深色品牌背景区（含品牌墙） | 图文内容 | 否 | eyebrow、title[]、paras[]、pillars[]、image、backers[]、brandWall[] |
| cat-grid | 类别卡片（场景/政策） | 图文内容 | 否 | eyebrow、title[]、desc、theme、items[{num,icon,title,text,bullets}] |
| cap-flow | 产品特性四宫格（深色） | 图文内容 | 否 | eyebrow、title[]、items[{step,title,text,tags}] |
| poster-grid | 图文海报网格（产品速览） | 图文内容 | 否 | eyebrow、title[]、desc、theme、moreText/moreLink、items[{image,tag,caption,link}] |
| feature-products | 精选产品 | 数据驱动 | 是 | eyebrow、title[]、desc、theme、limit、moreText/moreLink（数据取公开产品 API）|
| latest-news | 最新资讯 | 数据驱动 | 是 | eyebrow、title[]、desc、theme、limit、moreText/moreLink（数据取公开资讯 API）|
| product-grid | 产品矩阵列表 | 数据驱动 | 是 | eyebrow、title[]、desc、theme、pageSize（数据取公开产品 API）|
| news-feed | 资讯列表 | 数据驱动 | 是 | eyebrow、title[]、desc、theme、pageSize（数据取公开资讯 API）|
| pm-entry | 产品矩阵入口（大字横幅） | 数据驱动 | 否 | word、num、title、sub、desc、btnText、btnLink（纯 props 横幅，不请求 API）|
| faq-list | 常见问题 FAQ | 数据驱动 | 是 | eyebrow、title[]、desc、theme、category（数据取公开 FAQ API）|
| contact-form | 联系方式 + 申请表单 | 转化组件 | 否 | infoTitle、infoItems、formTitle、formDesc、typeOptions、agreeText、submitText |
| cta-banner | CTA 横幅 | 转化组件 | 否 | title、desc、btnText、btnLink |
| rich-text | 通用富文本 | 转化组件 | 否 | eyebrow、title[]、desc、theme、html |

> 「数据驱动」列指该区块在渲染时是否请求公开 API 取列表数据；`pm-entry` 虽归于「数据驱动」分组，但实际为纯 `props` 大字横幅，不请求 API。

> **设计取舍（文案+配图可配、结构固定）**：`product-grid` / `news-feed` 仅向管理端暴露区头文案（eyebrow / title / desc）、背景 `theme` 与每页条数 `pageSize`，产品/资讯**列表数据仍来自公开 API**，分类筛选、搜索、排序、分页等交互结构固定不可编辑；`poster-grid` 为纯 `props` 图文卡（配图 / 角标 / 说明 / 跳转均可编辑），版式由 `website.css` 的 `.poster-grid` 固定。

> 一致性约束：**`sectionRegistry.ts`（formSchema/defaultProps）↔ `pageDefaults.ts`（前台兜底）↔ `backend/sql/migrations/002_page_blocks.sql` + `003_list_blocks.sql`（种子）三方 props 结构必须保持一致**，任一侧修改需同步。

### 3.1 formSchema 字段类型（BlockForm 通用渲染）
共 10 种 kind：`text / textarea / html / number / image / select / lines / link / object / list`。
- `image`：URL 输入 + 「媒体库」按钮，弹出 `MediaPicker.vue` 选择/上传。
- `lines`：字符串数组 repeater（如多行标题）。
- `link`：固定 `{ text, link }` 子表单。
- `object` / `list`：递归复用 `BlockForm`；`list` 支持增删与上下移，条目标题支持 `{字段}` 占位。
- `select`：`options` 为 `{ label, value }[]`。

### 3.2 各导航页默认区块（种子 002 + 003，与设计稿一致）
- **home**：hero → intro-eco → mvv → values → feature-products → story → pm-entry → latest-news → cta-banner
- **about**：page-hero → intro-eco → timeline → story(含 brandWall) → cta-banner
- **products**：page-hero → **product-grid** → cat-grid → cap-flow → cta-banner（产品矩阵列表改由 product-grid 区块承载）
- **news**：page-hero → **news-feed** → **poster-grid** → **cta-banner**（资讯列表 / 速览海报 / 尾部 CTA 全部改为区块驱动）
- **contact**：page-hero → cat-grid → timeline → faq-list → contact-form → cta-banner

## 4. 编辑-草稿-发布时序

```
管理端编辑器                backend                     DB(pages)              官网前台
   │  by-slug/:slug  ────────▶ GET 整页(含 draft_json) ─┐
   │  ◀── blocks(优先草稿) ────────────────────────────┘
   │  编辑 props/增删/排序/显隐（仅内存）
   │  保存草稿 ──────────────▶ PUT /:id/draft ────────▶ draft_json=clean(blocks)   （content_json 不变，官网不变）
   │  发布   ────────────────▶ (先 saveDraft) POST /:id/publish
   │                            └ 事务: content_json=draft_json, status=1,
   │                               published_at=COALESCE(published_at,NOW())  ──▶ 官网即时生效
   │  下线   ────────────────▶ POST /:id/unpublish ───▶ status=0              ──▶ 公开接口不再返回
```
- 公开接口 `GET /public/pages/:slug` 仅返回 `status=1` 的 `content_json`，草稿不外泄。
- **缓存策略**：`/public/pages/:slug` 显式返回 `cache-control: no-cache` + `ETag`（`"pg{id}-{updated_at 毫秒}"`），命中 `If-None-Match` 时返回 304。`no-cache` 保证每次都用协商缓存校验最新版本，后台发布后前台**即时生效**（其余 `/public/*` 只读接口才使用 `PUBLIC_CACHE_MAX_AGE` 短缓存，处理器已设头时不覆盖）。
- **放弃草稿**：`DELETE /pages/:id/draft` 将 `draft_json` 复位为 `{}`，编辑器重载后回落官网线上版本。
- 预览仅在编辑器内完成（`SectionRenderer` 渲染内存中的草稿 `blocks`），不开放公开草稿预览链接。

## 5. Backend 改动

### 5.1 SQL 迁移（幂等，已执行）
- `backend/sql/migrations/002_page_blocks.sql`
  - `ALTER TABLE pages ADD COLUMN IF NOT EXISTS draft_json JSONB NOT NULL DEFAULT '{}'::jsonb;`
  - UPSERT 5 个页面种子（home/about/products/news/contact），`content_json` 与 `draft_json` 初始化为与设计稿一致的完整 blocks；仅当原 `content_json = '{}'` 时填充，不覆盖管理端已保存内容。
- `backend/sql/migrations/003_list_blocks.sql`
  - 用 JSONB 切片在 `page-hero`（第 1 块）之后插入区块：products 页插 `product-grid`，news 页依次插 `news-feed` → `poster-grid` → `cta-banner`。
  - 幂等：仅当 `content_json::text NOT LIKE '%"product-grid"%'`（news 判 `"news-feed"`）才插入，只做「插入」不重写整页，保留管理端已编辑的其余区块与顺序。
  - 当草稿也已结构化（`draft_json ? 'blocks'` 且不含该 type）时同步写回 `draft_json`。

### 5.2 接口（`backend/src/routes/content.ts`）
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/pages` | 列表（精简列 + `has_unpublished_draft`） |
| GET | `/api/pages/by-slug/:slug` | 按 slug 取整页（含 draft），编辑器用 |
| GET | `/api/pages/:id` | 详情（含 draft） |
| POST | `/api/pages` | 新建，两 JSON 同初始化 |
| PATCH | `/api/pages/:id` | 仅 meta（title/metaTitle/metaDescription/heroImage） |
| PUT | `/api/pages/:id/draft` | 保存草稿，body `{ contentJson }`，`deepSanitize` 清洗 |
| DELETE | `/api/pages/:id/draft` | 放弃草稿：`draft_json` 复位为 `{}`，编辑器回落线上版本 |
| POST | `/api/pages/:id/publish` | 草稿覆盖正式 + 上线（草稿无 blocks 数组时拒绝，避免清空线上） |
| POST | `/api/pages/:id/unpublish` | 下线 status=0 |
| DELETE | `/api/pages/:id` | 删除 |
| POST | `/api/articles/:id/unpublish` | 资讯下线 status=2（公开接口按 status=1 过滤，前台不再展示） |
| PATCH | `/api/media/:id` | 素材改名（originalName）/归类（category），**不改动访问 `url`**，避免已发布内容失效 |
| DELETE | `/api/media/:id` | 删除素材：先跨 pages/products/articles/banners 扫描 `object_key` 引用，被引用则 409 拒绝，否则删记录并尽力清除物理文件 |
| POST | `/api/{banners,faqs,menus,product-categories,article-categories}/reorder` | 批量排序，body `{ items:[{id,sort}] }`，单事务提交（上下移/拖拽后整体回写） |

- 权限沿用 `content:read` / `content:write`；`:id` 全局校验正整数。
- 富文本叶子经 `deepSanitize` 递归 XSS 清洗；写操作记 `audit_logs`。
- 除上表新增/调整的 pages 双版本、articles 下线、media 改名/删除与 `*/reorder` 批量排序外，其余内容接口（products/articles/categories/banners/faqs/settings/menus 的 CRUD）、线索（forms.ts）、上传（upload.ts）、用户角色（users.ts）沿用既有实现，管理端直接对接。

## 6. 官网前台改造（buinessweb/src/website + views/website）

- `website/blocks.ts`：Block/PageContent 类型 + `parseBlocks / genBlockId / moveBlock / removeBlock / insertBlock`。
- `website/sections/*.vue`：19 个区块组件（含新增 `SecProductGrid.vue` / `SecNewsFeed.vue` / `SecPosterGrid.vue`；从原 Home/About/Contact 模板拆出，沿用 website.css 类）。
- `website/sectionRegistry.ts`：type → 元数据 + formSchema；`SECTION_GROUPS`、`sectionLabel()`。
- `website/SectionRenderer.vue`：按 `blocks.filter(visible)` 顺序渲染并透传 `props`（`preview` 模式供编辑器复用）。
- `website/usePageBlocks.ts`：拉取 `cms.getPage(slug)` 覆盖 `pageDefaults` 内置兜底 blocks；接口失败/空内容时保留兜底，**官网永不白屏**。
- 页面重构：
  - Home / About / Contact：整页区块驱动（Home 含 Banner 覆盖 hero.image，处理 banner 与远程区块的时序竞态）。
  - Products / News：页面组件不再硬编码列表区，改为 `usePageBlocks(slug)` 拉取区块 + `SectionRenderer` 渲染整页；产品矩阵/资讯列表分别由 `product-grid` / `news-feed` 区块承载（区头文案可编辑，列表数据仍走公开 API、筛选/分页结构固定）。页面 SEO meta 由「页面信息」写入，`usePageBlocks` 成功后调用 `applyPageSeo` 同步 `document.title`（取 `meta_title`，回落 `title`）与 `meta[name=description]`（取 `meta_description`）。

### 7.3 装修编辑器（editor.vue，核心）
- **三栏**：左区块列表（新增/删除/上下移/显隐/选中）；中 `BlockForm`（按 `formSchema` 通用渲染）；右 `SectionRenderer`（草稿实时预览，1280 定宽 + transform 缩放）。
- **顶栏**：保存草稿、发布（先存草稿再 publish，二次确认「立即覆盖线上」）、下线、放弃草稿（`DELETE /:id/draft` 后重载回落线上版本）、页面信息（SEO meta）、返回（脏时二次确认）。
- **新增区块**：弹窗按 `SECTION_GROUPS` 分组选择类型 → `defaultProps()` + `genBlockId()` → 插入选中项之后。

### 7.4 复用组件
- `MediaPicker.vue`：媒体库浏览 + 本地直传上传弹窗，`v-model:visible` + `@select(url)`；供编辑器 image 字段与各表单复用。
- `BlockForm.vue`：schema 驱动通用表单，object/link/list 递归复用（`defineOptions({ name:'BlockForm' })`）。
