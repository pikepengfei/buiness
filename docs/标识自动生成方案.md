# 标识（slug）改为系统自动生成 · 实施方案

> 状态：**已评审、已落地（2026-11-03）**。原方案的影响面盘点有 7 处偏差，评审后按 §8 订正执行；§3–§6 中被订正的条目已就地改写并标注「落地订正」，未订正的条目保持原样。落地记录与实测结果见 §8。
> 决策记录（2026-11-02 需求方确认）：生成规则 = **B 不透明短码**；范围 = **产品/资讯内容 + 两类分类一并处理**；存量 = **全部保留不动**；生成方与时机 = **后端在提交/保存时生成并写入 slug 字段**；前端 = **字段显示位置不变**，仅由输入框改为只读展示。

## 1. 为什么要改

现状由运营手工填写标识，带来三类成本：

1. **运营负担**：每条内容要想一个合法且未被占用的标识，中文名还要自己翻成英文。
2. **改名即改址**：标识决定官网地址，改名会让旧链接失效——产品链为此专门做了「改标识后果弹窗」，资讯链也有对应场景，都是为手工填写兜的额外复杂度。
3. **两链校验不对称**：产品侧有格式 regex，资讯侧没有（实测大写 `Bad-Slug` 被接受），资讯分类连长度校验都没有。该缺口已登记在 `article-content-flow/design.md`「已知缺口」与 `tasks.md` 第 12 组。

改为系统生成后，第 2、3 类成本自然消解。

## 2. 目标与非目标

**目标**
- 运营不再手工输入标识：**后端在提交/保存时生成**并写入 `slug` 字段。
- 前端**字段显示位置保持不变**（仍在表单/列表原位置），仅由可编辑输入框改为只读展示。
- 标识一经生成即冻结：改名称/标题不影响官网地址。
- 存量标识全部保留，已发布的官网地址、外链、物料二维码继续有效。
- 两类分类标识同样改为自动生成，消除两链不对称。

**非目标**
- 不改公开地址结构（仍是 `/product/:slug`、`/article/:slug`），C1 地址白名单不受影响。
- 不动 `uid`（跨表稳定身份）、不动双表搬运语义、不动发布/下架流程。
- 不引入新 npm 依赖。

## 3. 生成规则（方案 B · 不透明短码）

| 项 | 规则 |
|---|---|
| 形态 | `{类型前缀}-{6位随机}`，如 `p-k3f9qz`（产品）、`a-7hd2mx`（资讯）、`pc-`…（产品分类）、`ac-`…（资讯分类） |
| 字符集 | `[a-z0-9]`，6 位 → 36^6 ≈ 20 亿组合 |
| **生成方与时机** | **后端**在**提交/保存**（`POST` 创建草稿 / 分类创建）落库那一刻生成并写入 `slug` 列；前端不生成、不传该字段 |
| 首次保存前 | 库里还没有该行，界面显示占位「保存后自动生成」，不预生成、不佔号 |
| 已保存后 | 值随读取下发，界面只读展示；`PATCH` 不再携带、也不再改写 |
| 唯一性 | **落地订正**：既有预检函数签名不回用（它们「查完即 `reply` 报错」，无法当布尔判定用），改为新增谓词 `isSlugTaken`（本表，分类用）与 `isContentSlugTaken`（跨线上表 + 未上线表，内容用）；生成时逐个候选查重，冲突重试上限 5 次；仍冲突则依赖 `UNIQUE` 约束转 409，**不静默改名** |
| 冻结 | 生成后不再变更；改名不触发重生成；发布/下架搬运随行 |
| 响应契约 | `POST` 创建响应**新增返回 `slug`**（现返回 `{id, uid, stripped_images}`），前端据此即时回填展示，不必等重新取数 |

**为什么不在前端生成**：前端生成会与后端校验分叉（两条链校验本就不对称），且刷新/并发下易产生脏值；由后端在落库同一事务内生成 + 查重，唯一性只由一处保证。

**为什么不用拼音**：项目约定「不轻易新增 npm 依赖」，且多音字/生僻字转写不可靠；中文名转拼音会得到长而不可读的串，反而更差。

## 3.1 对已登记不对称的处置结论（2026-11-02 实测）

`article-content-flow/tasks.md` 第 12 组登记的 5 项，在本方案下的逐项结论：

| 项 | 结论 | 依据 |
|---|---|---|
| 12.1 资讯内容标识缺格式校验 | ✅ **消解** | 不再接受外部输入，生成值必合规，格式问题无从产生 |
| 12.2 资讯分类标识缺长度/格式校验 | ✅ **消解** | 分类标识一并改为自动生成 |
| 12.3 资讯 spec 缺「标识格式非法」场景 | ⚠️ **失效需改写**（不算"通过"） | 无输入口 → 该场景不可验收，应删除或改写为"不接受外部标识"；产品侧同场景同样处理 |
| 12.4 前端标识格式提示 | ✅ **消解** | 无输入框即无提示需求 |
| 12.5 补齐前先查存量 | ❌ **仍需执行**（非假设项） | 实测 `articles` id=7 的 slug 为 `大法师的`（纯中文、`status=1` 已上线），官网地址 `/article/大法师的`；正是缺校验造成的实际损害 |

**实测存量盘点**（7 张表全量）：仅 `articles` 有 1 条不合规，其余 6 张表（products / product_drafts / article_drafts / product_categories / article_categories / pages）全部合规。

**12.5 的处置建议**：本方案保留存量不动，那条中文标识继续可用；是否改写需运营确认（改标识即改官网地址，会让已发布的 `/article/大法师的` 失效）。建议单独决策，不混入本方案。

**改造后新增的不对称点（需新登记）**：装修页 `pages` 的 slug（`content.ts:187`，仅 `min(1).max(80)`、无格式校验）**仍为手工填写**——页面地址（`/about`、`/products`）语义化且被 C1 地址白名单固定，不适合自动生成，故保留手工；但它同样缺格式校验，是改造完成后唯一的"手工 + 无校验"残留点，建议一并登记。

## 5. 风险与不可逆点

| 风险 | 影响 | 缓解 |
|---|---|---|
| **新内容 URL 失去语义** | SEO 弱于语义化地址；运营看不懂 | 列表/编辑页显式展示完整地址 + 复制按钮（现已有）；后续如需语义化可再加转写 |
| **不可逆** | 新建内容的短码无法自动变回语义 slug | 存量不动；可先小范围试点再全量 |
| 撞存量概率 | 极低 | 查重重试 + `UNIQUE` 兜底转 409 |
| 并发创建 | 同瞬间生成同一短码 | 随机熵足够 + UNIQUE 约束兜底，其二失败走重试 |
| 运营习惯 | 失去"自己定地址"的控制感 | 界面明确说明「地址由系统生成，改名不影响」 |
| **分类标识同时是官网筛选参数（原方案未列，评审补入）** | `?category=` 的取值由可读词变成 `pc-xxxxxx`/`ac-xxxxxx`；`categoryCond()` 的非数字分支按 slug 解析，链接可分享性下降 | 保留数字 id 分支（`"5"` 与 `5`、`pc-xxx` 三种写法命中同一集合，已实测）；分类列表「标识」列只读回显，运营可复制 |

## 6. 任务分解

1. 后端：生成器（**落地订正：`randomSlug` + `isSlugTaken`/`isContentSlugTaken` + `genSlug` 四个函数，不是一个 `genContentSlug`**）；在**保存/创建**路径生成并写入 `slug` 列（产品/资讯草稿 + 两类分类，两链各改、互不引用）
2. 后端：创建接口不再接收外部 slug（忽略或 400）；`POST` 响应**新增返回 `slug`**
3. 后端：`PATCH` 不再改写 slug（收到即忽略），保持冻结
4. 前端：两个编辑页**原位**改为只读展示（未保存占位 / 已保存显示短码+地址）；删除必填校验、格式正则、改标识弹窗与 `savedSlug`
5. 前端：`types/cms.ts`（Payload 去 slug、创建结果加 slug）+ `api/cms.ts` 收敛
6. openspec：两份 spec delta 改写 + proposal/design/config 同步；`article-content-flow` 第 12 组标注「由本方案消解」
7. 文档：**六份** `docs/*` 回写 + `backend/sql/schema.sql` 六处列注释（**落地订正**：原列的四份之外还要动 `docs/后端执行文档.md` 与 `docs/数据库执行文档.md`，详见 §4.4 补入清单）
8. 验证：新建→**保存后 slug 生成并回填展示**→改名称→slug 与地址不变→发布→详情可访问→下架→再发布→slug 随行不变→**存量老地址仍 200**→重复生成不撞；前端不再有标识输入框但有只读显示位
9. 两端类型检查：`npx tsc --noEmit` + `npx vue-tsc --noEmit -p tsconfig.vitest.json --composite false`

## 7. 回滚

- 代码：表单加回即可（`git revert` 按后端/前端/文档分桶），无数据迁移故无迁移回滚。
- 数据：存量 slug 从未改动；期间新建的短码 slug 保留（不会自动变回语义 slug，这是唯一不可逆点，但不影响可用性）。
