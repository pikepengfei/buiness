# 页面编辑 · 草稿-发布-官网显示 实现方案

> 日期：2026-10-28
> 范围：基于《官网页面类型方案调研与匹配分析》的落地建议（P1 预览增强、P3 区块 Schema 版本化），对 `z-buiness` 现有「区块化页面构建器」做实现与补强。
> 结论先行：**编辑→草稿→发布→官网显示 的核心链路在既有代码中已完整实现**，本次实现聚焦于两处真实缺口：① 区块结构向前兼容版本化（P3）；② 真机布局下的草稿预览入口（P1 增强）。

## 1. 本次实现内容

### 1.1 P3 — 区块 Schema 版本化（向前兼容迁移）

**问题**：区块结构（props/字段约定）随业务演进会变化；历史区块 JSON 直接重存迁移有「一次性事务打爆生产页」的风险（kuray.dev 复盘）。既有代码无版本概念。

**方案（前端优先、零数据库依赖）**：在每次读取区块时做「向前兼容迁移」，而非改动存储：
- `buinessweb/src/website/blocks.ts`：
  - 新增 `CURRENT_BLOCK_SCHEMA_VERSION = 1` 常量；
  - 新增 `MIGRATIONS: Array<(b)=>Block>` 迁移阶梯（索引即 fromVersion），当前含 `v0→v1` 结构化兜底（确保 `visible` 为布尔、`props` 为对象、剥离内部版本标记）；
  - 新增 `migrateBlock(b)`，从区块自带版本号循环迁移到当前版本；
  - `parseBlocks()` 在解析后对每个区块执行 `migrateBlock` —— 编辑器、官网显示、公开接口**三处读取自动获得兼容**。
- `buinessweb/src/types/cms.ts`：`Page` / `PageListRow` 增加可选 `schema_version`。
- `backend/sql/migrations/005_pages_schema_version.sql`（**可选、生产加固**）：为 `pages` 增加 `schema_version INTEGER NOT NULL DEFAULT 1` 并回填历史行，使「哪些页待升级」可查询。因当前环境无 `psql`，该文件作为待执行 artifact 提供；在前端迁移已保证渲染安全的前提下，**不强制立即执行、不修改后端写入逻辑**，避免破坏运行中的开发后端。

> 该方案对应业界「向后兼容读取 + 在内存中逐页迁移 + 可查询版本号」三项约束，且不在数据库层做破坏性迁移。

### 1.2 P1 增强 — 真机布局草稿预览

**问题**：既有预览仅为编辑器内缩放画布，运营无法在「真实导航/页脚布局」下确认发布效果。

**方案**：
- 新增 `buinessweb/src/views/website/Preview.vue`：读取 `GET /pages/by-slug/:slug` 的 `draft_json`（无草稿回退线上），在 `WebsiteLayout` 真实布局内用 `SectionRenderer(preview)` 渲染，顶部固定「草稿预览」提示条，仅登录运营可见。
- `buinessweb/src/router/index.ts`：新增子路由 `/preview/:slug`，`meta.requiresAuth=true`（复用全局登录守卫）。
- `editor.vue` 预览栏新增「预览草稿 ↗」链接，新标签打开该路由。

## 2. 端到端数据流

```
[运营] editor.vue
   │  编辑区块（BlockForm 按 formSchema 改 props）
   │  PUT /api/pages/:id/draft  ──►  backend: draft_json = deepSanitize(blocks)   [草稿态，官网不可见]
   │
   ├─ 发布  POST /api/pages/:id/publish
   │        └─►  content_json = draft_json; status = 1   [原子切换，发布即时生效]
   │
   └─ 预览草稿  /preview/:slug  (requiresAuth)
            └─►  GET /pages/by-slug/:slug → draft_json → SectionRenderer(preview)  [真实布局，未发布]

[官网] usePageBlocks(slug)  onMounted
   └─►  GET /api/public/pages/:slug  (no-cache + ETag)
        └─►  content_json（status=1）→ SectionRenderer  ──► 展示
```

兼容与回滚：
- 放弃草稿：`DELETE /api/pages/:id/draft` 清空 `draft_json`，编辑器回落线上版。
- 下线：`status=0`，公开接口过滤，官网即撤下。
- 历史区块：任何读取经 `parseBlocks → migrateBlock` 自动归一化，老页面无需重存即可渲染。

## 3. 验证建议

- 类型检查：`cd buinessweb && npx vue-tsc --noEmit`（区块版本化改动均在 `blocks.ts` 内，影响面小）。
- 手动走查：新建/编辑一个页面 → 保存草稿 → 编辑器内实时预览 + 「预览草稿」真机预览 → 发布 → 官网对应路由即时生效 → 下线即撤下。
- 版本化：可临时构造一个缺 `visible`/`props` 的旧格式区块 JSON 存入 `draft_json`，确认 `parseBlocks` 能归一化渲染（不报错）。
